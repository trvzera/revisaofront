Como estudar com este guia

Leia um tópico, tente prever o resultado do código e só depois execute. Mantenha index.html e script.js abertos para comparar a explicação com o projeto. Os exemplos pequenos são independentes: não é necessário colar todos no mesmo arquivo.

Para acompanhar console.log(), abra as ferramentas de desenvolvedor do navegador com F12 e selecione Console. Para estudar o armazenamento, procure Application/Aplicativo → Storage/Armazenamento. Os nomes podem variar conforme o navegador.

1. Como o JavaScript se conecta ao HTML

O HTML define os elementos da página. O CSS define a aparência. O JavaScript lê informações, toma decisões e altera os elementos em resposta a ações.

No seu projeto, o arquivo JavaScript é carregado no final do body, sem defer:

<body>
  <p id="mensagem">Texto inicial</p>

  <script src="script.js"></script>
</body>

O navegador analisa o HTML em ordem. Quando chega ao script, o parágrafo já existe e pode ser encontrado pelo JavaScript.

const paragrafo = document.querySelector("#mensagem");
paragrafo.textContent = "Texto alterado pelo JavaScript";

Leia a primeira linha assim: “Encontre o elemento com id mensagem e guarde uma referência a ele na variável paragrafo”. O símbolo # faz parte do seletor e indica um ID. No HTML, o ID é escrito sem #.

A segunda linha altera o texto dentro daquele elemento. A página passa a mostrar “Texto alterado pelo JavaScript”.

O nome da variável não precisa ser igual ao ID. Poderíamos chamá-la de elemento ou resultado; o que identifica o elemento é o seletor "#mensagem".

Se você colocar esse script no head sem defer, ele poderá executar antes de o parágrafo existir. Nesse momento, querySelector retorna null e tentar acessar textContent causa erro. Para os exemplos deste guia, mantenha o script antes de </body>, como no seu projeto. Outra opção seria usar defer no head.

2. Variáveis e tipos de dados

2.1 O que é uma variável?

Uma variável é um nome associado a um valor que o programa usa. Por exemplo, o nome de um aluno, uma nota ou o resultado de uma média.

let nota = 6;
nota = 8;

const nome = "Ana";
console.log(nome, nota); // Ana 8

let permite reatribuir o valor: nota começou com 6 e depois recebeu 8. const impede reatribuição: tentar executar nome = "Bia" gera erro.

var é uma forma mais antiga de declaração. Uma diferença importante é o escopo: let e const respeitam blocos delimitados por chaves; var tem escopo de função ou global.

if (true) {
  let aviso = "Olá";
}

// console.log(aviso); // Erro: aviso só existe dentro do bloco.

No projeto, const é usado para referências aos elementos e let alunos = [] permite substituir o array quando um cadastro é excluído.

JavaScript tem outros tipos primitivos, como bigint e symbol, mas os exemplos acima cobrem os tipos usados neste projeto. Arrays são objetos; Array.isArray(valor) verifica especificamente se um valor é um array.

const aluno = { nome: "Ana", nota: 8 };
const notas = [8, 6, 10];

Uma const pode apontar para um objeto ou array que seja modificado:

// nomes = [];    // Erro: tenta reatribuir a variável.

2.3 Por que converter o valor do input?

const campo = document.querySelector("#nota1");
const texto = campo.value;
const numero = Number(texto);

Mesmo em um input type="number", a propriedade value fornece uma string. Se você digitar 8, texto será "8" e numero será 8.

console.log("8" + "6");                 // "86"
console.log(Number("8") + Number("6")); // 14

O operador + pode concatenar textos ou somar números. Por isso o projeto converte as notas antes do cálculo.

Atenção: Number("") resulta em 0 e Number("abc") resulta em NaN, um valor que indica falha de conversão numérica. Converter não substitui validar. No formulário, required impede o envio comum de campos vazios, e min/max limitam as notas.

3. Lógica condicional

3.1 Como funciona if, else if e else?

Uma condição escolhe qual bloco executar. A comparação produz true ou false.

const media = 6;

if (media >= 7) {
  console.log("Aprovado");
} else if (media >= 5) {
  console.log("Recuperação");
} else {
  console.log("Reprovado");
}

Passo a passo: 6 >= 7 é falso, então o primeiro bloco é ignorado. Depois, 6 >= 5 é verdadeiro, então aparece “Recuperação”. O bloco else não é executado.

Em uma cadeia if/else if/else, apenas o primeiro bloco com condição verdadeira é escolhido. A ordem importa: se media >= 5 fosse testado primeiro, uma média 8 também entraria nesse bloco.

== permite conversões ao comparar: 8 == "8" resulta em true. Prefira === quando quiser comparar também o tipo.

const nota = 12;
if (nota < 0 || nota > 10) {
  console.log("Nota fora do intervalo");
}

Aqui basta uma das condições ser verdadeira para exibir o aviso.

3.3 Ternário e switch

O ternário escolhe um de dois valores:

const mensagem = media >= 7 ? "Aprovado" : "Não aprovado";

Leia: se a condição for verdadeira, use o primeiro valor; se for falsa, use o segundo.

O switch compara um valor com opções específicas:

const acao = "salvar";
switch (acao) {
  case "salvar":
    console.log("Salvar cadastro");
    break;
  case "excluir":
    console.log("Excluir cadastro");
    break;
  default:
    console.log("Ação desconhecida");
}

break interrompe o switch. Sem ele, a execução pode seguir para os próximos casos.

4. Funções

4.1 Declarar, chamar e receber um resultado

Uma função agrupa instruções para realizar uma tarefa. Declarar a função prepara a tarefa; chamar a função executa seu corpo.

function calcularMedia(nota1, nota2) {
  return (nota1 + nota2) / 2;
}

const media = calcularMedia(8, 6);
console.log(media); // 7

Na declaração, nota1 e nota2 são parâmetros: nomes que receberão os dados. Na chamada, 8 e 6 são argumentos: os valores fornecidos.

Durante a execução, nota1 vale 8 e nota2 vale 6. A expressão (8 + 6) / 2 resulta em 7. return devolve esse 7 para a chamada, e const media guarda o resultado.

Os nomes não criam ligações automáticas entre variáveis. É a passagem dos argumentos que entrega os valores aos parâmetros.

4.2 O que return faz?

return devolve um valor e encerra aquela execução da função.

function verificarSituacao(media) {
  if (media >= 7) {
    return "Aprovado";
  } else if (media >= 5) {
    return "Recuperação";
  } else {
    return "Reprovado";
  }
}

const situacao = verificarSituacao(7);

Nesse exemplo, situacao recebe a string "Aprovado". Nada aparece automaticamente no HTML. Para exibir, será necessário alterar um elemento do DOM.

console.log e return têm papéis diferentes:

function apenasMostrar() {
  console.log(10);
}

const resultado = apenasMostrar();
// O console mostra 10, mas resultado recebe undefined.

Sem return com um valor, uma função comum termina devolvendo undefined.

4.3 Outras formas de escrever funções

const dobrar = function (numero) {
  return numero * 2;
};

const triplicar = (numero) => {
  return numero * 3;
};

const quadruplicar = numero => numero * 4;

A última arrow function tem retorno implícito: a expressão após a seta é devolvida sem escrever return. Com um corpo entre chaves, você precisa escrever return para devolver esse resultado.

5. DOM e eventos: como o resultado chega à tela

5.1 O que é DOM?

DOM é a representação do documento como uma árvore de objetos. Cada elemento HTML pode ser acessado e modificado por JavaScript.

Os passos mais comuns são: selecionar um elemento, registrar um evento, ler os valores, processar os dados e atualizar a página.

5.2 Exemplo completo e pequeno da média

Este exemplo pode ser usado em dois arquivos separados para estudar o fluxo básico.

HTML:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <title>Estudo da média</title>
</head>
<body>
  <form id="formulario">
    <label for="nota1">Primeira nota</label>
    <input id="nota1" type="number" min="0" max="10" step="0.1" required>

    <label for="nota2">Segunda nota</label>
    <input id="nota2" type="number" min="0" max="10" step="0.1" required>

    <button type="submit">Calcular</button>
  </form>

  <p id="resumo">Aguardando notas.</p>
  <script src="script.js"></script>
</body>
</html>

JavaScript:

const formulario = document.querySelector("#formulario");
const campoNota1 = document.querySelector("#nota1");
const campoNota2 = document.querySelector("#nota2");
const resumo = document.querySelector("#resumo");

function calcularMedia(nota1, nota2) {
  return (nota1 + nota2) / 2;
}

function verificarSituacao(media) {
  if (media >= 7) return "Aprovado";
  if (media >= 5) return "Recuperação";
  return "Reprovado";
}

formulario.addEventListener("submit", function (evento) {
  evento.preventDefault();

  const nota1 = Number(campoNota1.value);
  const nota2 = Number(campoNota2.value);
  const media = calcularMedia(nota1, nota2);
  const situacao = verificarSituacao(media);

  resumo.textContent = `Média: ${media.toFixed(2)} — ${situacao}`;
});

Entenda cada etapa ao enviar notas 8 e 6:

1. O navegador já criou os elementos quando o script é executado.

2. querySelector encontra cada elemento pelo ID.

3. addEventListener registra a função que deverá executar no envio do formulário. O cálculo ainda não aconteceu.

4. O usuário preenche as notas e envia o formulário.

5. preventDefault impede o envio padrão, que poderia navegar ou recarregar a página.

6. campoNota1.value fornece "8" e campoNota2.value fornece "6".

7. Number transforma os textos em números.

8. calcularMedia(8, 6) devolve 7.

9. verificarSituacao(7) devolve "Aprovado".

10. resumo.textContent coloca “Média: 7.00 — Aprovado” no parágrafo.

A conexão com o que aparece na tela está na atribuição a textContent. A função verificarSituacao apenas escolhe e devolve o texto.

toFixed(2) formata um número com duas casas decimais e devolve uma string. Ele não modifica a variável media. As crases permitem inserir valores no texto com ${...}.

5.4 Eventos e funções de resposta

click representa um clique; input acompanha mudanças durante a digitação; submit representa o envio do formulário. A função entregue ao listener é chamada quando o evento acontece.

function avisar() {
  console.log("Você clicou!");
}

botao.addEventListener("click", avisar);

Aqui passamos avisar sem parênteses para registrar a função. Escrever avisar() executaria a função naquele momento e passaria seu retorno ao listener.

5.5 Criando elementos na lista

const lista = document.querySelector("#lista-alunos");
const item = document.createElement("li");
item.textContent = "Ana — Aprovado";
lista.appendChild(item);

createElement cria o elemento, mas não o coloca na página. appendChild insere o item na lista. No projeto, forEach repete a criação para cada aluno do array.

lista.replaceChildren() esvazia os filhos da lista antes de reconstruí-la. Isso evita duplicação dos itens na tela.

6. Máscaras de entrada

6.1 O que é uma máscara?

Uma máscara formata o valor digitado. Por exemplo, transforma 12345678901 em 123.456.789-01. A formatação não comprova que o CPF existe nem que seus dígitos verificadores estão corretos.

<input id="cpf" type="text" inputmode="numeric" maxlength="14">

type="text" permite exibir pontos e hífen. inputmode="numeric" sugere um teclado numérico em dispositivos compatíveis, mas não bloqueia letras sozinho. maxlength conta todos os caracteres, incluindo a pontuação.

const campoCpf = document.querySelector("#cpf");

function aplicarMascaraCpf(valor) {
  return valor
    .replace(/\D/g, "")
    .slice(0, 11)
    .replace(/(\d{3})(\d)/, "$1.$2")
    .replace(/(\d{3})(\d)/, "$1.$2")
    .replace(/(\d{3})(\d{1,2})$/, "$1-$2");
}

campoCpf.addEventListener("input", function () {
  campoCpf.value = aplicarMascaraCpf(campoCpf.value);
});

O fluxo é: usuário digita → evento input → leitura de value → função formata → atribuição a value → campo exibe o texto formatado.

Observe que return sozinho não altera o campo. A mudança visual acontece porque o retorno é atribuído a campoCpf.value.

6.2 Entendendo a expressão regular

Expressões regulares descrevem padrões de texto. Neste exemplo:

TrechoSignificado
\DCaractere que não é um dígito
gAplicar a substituição a todas as ocorrências encontradas
\dUm dígito de 0 a 9
{3}Exatamente três repetições
{1,2}Uma ou duas repetições
(...)Grupo de captura
$1 e $2 no texto de substituiçãoConteúdo do primeiro e segundo grupos
$ no final do padrãoFinal do texto

replace procura um padrão e devolve um novo texto com a substituição. slice(0, 11) devolve até os primeiros 11 caracteres. As strings originais não são modificadas por esses métodos; cada etapa entrega o resultado à próxima.

Para a entrada 12345678901, acompanhe os resultados:

Remover não dígitos: 12345678901
Limitar a 11:        12345678901
Primeiro ponto:     123.45678901
Segundo ponto:      123.456.78901
Hífen final:        123.456.789-01

7. localStorage e sessionStorage

7.1 Variável e armazenamento têm durações diferentes

Uma variável comum existe durante a execução da página. Ao recarregar, o código inicia novamente. Storage permite guardar textos no navegador e recuperá-los depois.

Salvar não é exibir: depois de recuperar os dados, você ainda precisa atualizar os campos ou criar os elementos no DOM.

CaracterísticalocalStoragesessionStorage
Recarregar a páginaMantém os dadosMantém os dados
Fechar a abaPode manter para acessos futurosA sessão normalmente termina
CompartilhamentoEntre páginas da mesma origemPor origem e sessão da aba
Uso no projetoLista de alunosRascunho do formulário

Origem é a combinação de protocolo, domínio e porta. Por exemplo, duas portas diferentes de localhost têm armazenamentos separados. Prefira testar o projeto por um servidor local, como o Live Server; o comportamento em URLs file: pode variar.

localStorage não é um banco de dados de servidor e não sincroniza automaticamente com outro dispositivo. Os dados podem ser apagados pelo usuário ou navegador. Não guarde senhas nesses armazenamentos.

7.2 Salvar, ler e remover

localStorage.setItem("nome", "Ana");

const nomeSalvo = localStorage.getItem("nome");
console.log(nomeSalvo); // "Ana"

localStorage.removeItem("nome");

"nome" é a chave usada para localizar o valor. "Ana" é o valor. A leitura usa a mesma chave da gravação.

Se a chave não existir, getItem retorna null. removeItem remove uma chave. clear remove todas as chaves daquele armazenamento na origem atual; por isso o projeto prefere operações específicas.

Para usar sessionStorage, os métodos são iguais:

sessionStorage.setItem("etapa", "2");
const etapa = sessionStorage.getItem("etapa");
sessionStorage.removeItem("etapa");

Mesmo que você salve um número diretamente, ele é convertido em texto:

localStorage.setItem("nota", 8);
const nota = localStorage.getItem("nota");
console.log(typeof nota); // "string"

7.3 Objetos e arrays: por que usar JSON?

Para guardar os dados estruturados de um aluno, converta-os em texto JSON. Na leitura, faça a conversão de volta.

const aluno = { nome: "Ana", media: 7 };

localStorage.setItem("aluno", JSON.stringify(aluno));

const texto = localStorage.getItem("aluno");
if (texto !== null) {
  const alunoRecuperado = JSON.parse(texto);
  console.log(alunoRecuperado.nome); // "Ana"
  console.log(alunoRecuperado.media); // 7
}

JSON.stringify transforma o objeto em uma string como '{"nome":"Ana","media":7}'. JSON.parse interpreta esse texto e devolve um objeto com as propriedades correspondentes.

O mesmo vale para um array de alunos. No projeto, alunos.push(aluno) adiciona um objeto ao array, e salvarAlunos grava a representação JSON desse array.

7.4 Como o rascunho reaparece no campo?

const campoNome = document.querySelector("#nome");

campoNome.addEventListener("input", function () {
  sessionStorage.setItem("rascunhoNome", campoNome.value);
});

const rascunho = sessionStorage.getItem("rascunhoNome");
if (rascunho !== null) {
  campoNome.value = rascunho;
}

Ao digitar, o evento salva o texto. Ao recarregar, o código lê a chave. A linha campoNome.value = rascunho é a responsável por colocar o texto de volta no campo.

7.5 Por que o projeto tem try e catch?

try {
  localStorage.setItem("nome", "Ana");
} catch (erro) {
  console.error(erro);
}

try contém uma operação que pode falhar. Se houver um erro, catch recebe esse erro e permite tratá-lo. O navegador pode bloquear armazenamento, ficar sem espaço, ou haver texto JSON inválido salvo. Isso explica os blocos de tratamento no projeto.

8. O caminho completo no projeto de alunos

Ao abrir a página, as chamadas ao final de script.js recuperam o rascunho, carregam os alunos e montam a lista. Declarar as funções anteriormente não as executa por si só.

Ao enviar o formulário, o fluxo principal é:

Usuário preenche e envia
        ↓
Evento submit executa a função registrada
        ↓
Leitura dos campos com .value
        ↓
Conversão das notas com Number()
        ↓
calcularMedia() devolve um número
        ↓
verificarSituacao() devolve uma string
        ↓
textContent e classList atualizam o resultado
        ↓
push adiciona o objeto ao array alunos
        ↓
JSON.stringify + setItem persistem a lista
        ↓
renderizarAlunos() cria os itens na página

renderizar é apenas o nome escolhido para a função que monta a exibição. O nome da função não tem um poder especial: quem altera a página são as operações executadas dentro dela.

12. Revisão rápida antes da prova

? Variável guarda um valor; o tipo influencia o comportamento das operações.

? .value lê ou altera um campo; .textContent lê ou altera texto de um elemento.

? Number converte; if escolhe; função organiza; return devolve.

? Uma função precisa ser chamada para executar seu corpo.

? addEventListener registra uma resposta a um evento.

? querySelector seleciona; createElement cria; appendChild insere.

? Máscara formata; validação verifica regras.

? localStorage e sessionStorage guardam strings.

? stringify prepara objetos para gravar; parse reconstrói valores a partir do JSON.

? Guardar ou retornar um valor não o exibe automaticamente: é necessário atualizar o DOM.
